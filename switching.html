Switching Project

Layer 2 switching problems with animated walkthroughs: VLANs and trunking, Spanning Tree, EtherChannel and port security.

Course: Switching & Routing

What is a switch, and what is a "switching problem"?

A switch connects devices inside one LAN. It learns each device's MAC address and forwards Ethernet frames only to the right port.

A switching problem is a Layer 2 design or fault question, such as: how do I separate groups of users (VLANs), stop loops when links are redundant (STP), use extra links efficiently (EtherChannel), or control who can plug in (port security)? This project solves one of each.

Problem 1: VLANs and Trunking

Sales (VLAN 10) and HR (VLAN 20) share two switches and one trunk.

vlan 10 / vlan 20 / vlan 99        interface gi0/1
interface fa0/1 → switchport access vlan 10   switchport mode trunk
interface fa0/2 → switchport access vlan 20   switchport trunk native vlan 99
What is the problem?

Sales and HR users are connected to the same switches, so all of them share one broadcast domain: every broadcast reaches everyone and there is no separation. The users are also spread over two switches, so each department must stay together across both.

Analogy: one big open office versus separate rooms for each department.

How it works
  1. A VLAN is a logical group of ports. Each access port belongs to exactly one VLAN.
  2. A switch forwards a frame only to ports in the same VLAN, so broadcasts stay within the VLAN.
  3. A trunk carries tagged frames between switches, and the receiving switch removes the tag before delivery to the final port.
  4. PC1 and PC3 share VLAN 10; PC2 and PC4 share VLAN 20. The trunk uses 802.1Q tagging.
How to solve it (steps)
  1. Make a plan table: VLAN IDs, names, ports, IP addresses.
  2. Create VLANs 10, 20, 99 on both switches.
  3. Set each access port: switchport mode access, then switchport access vlan X.
  4. Configure the trunk on both ends: mode trunk, native VLAN 99, allowed VLANs.
  5. Verify: show vlan brief, show interfaces trunk, then ping.

Common mistakes: VLAN missing on the second switch, VLAN not in the trunk's allowed list, native VLAN mismatch, wrong IP subnet on a PC.

Problem 2: Spanning Tree Protocol

Three switches in a triangle, FastEthernet links (cost 19), default priority.

spanning-tree vlan 1 priority 4096     ! make SW3 the root instead
show spanning-tree vlan 1
What is the problem?

Redundant links keep the network working if one cable fails, but they create a loop. Ethernet frames have no time-to-live, so a broadcast circles forever, causing a broadcast storm, an unstable MAC table and switches running at 100% CPU.

How it works
  1. Switches exchange BPDU messages (every 2 seconds) containing their Bridge ID = priority + VLAN ID + MAC.
  2. Root bridge: lowest Bridge ID wins (priority first, then lowest MAC).
  3. Root port: on every non-root switch, the port with the lowest total cost to the root. Costs: FastEthernet 19, GigabitEthernet 4.
  4. Designated port: on every link, one side forwards. The side with the lower cost to root wins; a tie goes to the lower Bridge ID.
  5. Any port that is neither root nor designated is blocked. It still listens for BPDUs.
  6. If a link fails, a blocked port moves to forwarding (listening, learning, forwarding).
How to solve it (steps)
  1. Write the Bridge ID of each switch.
  2. Find the lowest: that switch is the root.
  3. For each other switch, add up the cost to the root and pick the root port.
  4. For each link, decide the designated port (cost, then Bridge ID).
  5. Mark the remaining port as blocked.
  6. Verify with show spanning-tree.

To choose the root yourself: lower the priority in steps of 4096 (for example 4096).

Problem 3a: EtherChannel (LACP)

Fa0/23 and Fa0/24 between SW1 and SW2.

interface range fa0/23 - 24 → channel-group 1 mode active
interface port-channel 1 → switchport mode trunk      ! same on SW2
show etherchannel summary
What is the problem?

Two cables join SW1 and SW2 for more speed and safety, but STP blocks one of them to prevent a loop. So half the bandwidth is wasted and you only get a standby link.

How it works
  1. EtherChannel bundles up to 8 physical links into one logical Port-channel.
  2. STP treats the bundle as a single link, so nothing is blocked.
  3. Traffic is shared across the links by a hash of MAC or IP addresses. One conversation stays on one link; different conversations use different links.
  4. LACP (open standard) negotiates the bundle. Modes: active starts negotiation, passive only answers. Active+active or active+passive works; passive+passive does not.
  5. If one link fails, the others keep carrying traffic.
How to solve it (steps)
  1. Pick the ports (Fa0/23 and Fa0/24) on both switches.
  2. On both switches: channel-group 1 mode active.
  3. Configure interface port-channel 1 as a trunk.
  4. Verify: show etherchannel summary. Po1 should show SU and the ports P.

Common mistakes: member ports with different speed, duplex or VLAN settings; passive on both sides; mixing LACP and PAgP.

Problem 3b: Port Security

SW1 Fa0/1: maximum 2 MACs, sticky, violation shutdown.

interface fa0/1 → switchport port-security
  switchport port-security maximum 2 / mac-address sticky / violation shutdown
shutdown → no shutdown          ! recover from err-disabled
What is the problem?

Anyone can plug a laptop into a free network port and get access, or flood the switch with fake MAC addresses. The network needs a way to control which devices may use each port.

How it works
  1. The switch looks at the source MAC address of frames arriving on a single port.
  2. The port security feature records allowed MACs and compares each new source to the learned list.
  3. If the number exceeds the configured maximum, it triggers the configured violation action (shutdown, restrict, or protect).
  4. Sticky MACs automatically learn the addresses and save them to the running config.
  5. Violation shutdown puts the port into err-disabled until you recover with shutdown/ no shutdown.
How to solve it (steps)
  1. Set the port to access mode (port security needs a static access or trunk port).
  2. Enable it: switchport port-security.
  3. Set maximum 2, mac-address sticky, violation shutdown.
  4. Verify: show port-security interface fa0/1.
  5. After a violation, remove the intruder, then shutdown and no shutdown the port.
